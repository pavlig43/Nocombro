# Два склада: основной и для экспериментов

## Назначение

В приложении есть два фиксированных склада:

- `MAIN` — основной склад;
- `EXPERIMENTAL` — склад для экспериментов.

Основной склад содержит сырьё, которое можно использовать в производстве и продаже. На склад для экспериментов можно перенести просроченное сырьё, пробники, остатки для опытов и другие материалы, которые нельзя выдавать в обычное производство.

Склад для экспериментов не связан с журналом «Эксперименты». Номер опыта выбирать не нужно.

## Основные правила

1. Новые закупки и выпущенная продукция поступают на основной склад.
2. Перенос выполняется только вручную.
3. Уведомление о сроке годности ничего не переносит и не списывает.
4. Можно перенести часть партии.
5. Перенос между складами не меняет общий запас и его стоимость.
6. Списание уменьшает общий запас и прибыль.
7. Перенос и списание не создают платёж во вкладке «Деньги».
8. ОПЗС, продажи, страховой запас и уведомления используют только основной склад.

## Как пользоваться

### Перенос на склад для экспериментов

1. Открой вкладку «Склад».
2. Выбери `Основной`.
3. Раскрой нужный товар.
4. Нажми на строку партии.
5. Выбери «Перенести для экспериментов».
6. Укажи количество в килограммах.
7. Проверь дату операции.
8. Выбери причину.
9. При необходимости добавь комментарий.
10. Проверь остаток и стоимость выбранного количества.
11. Нажми «Сохранить».

После сохранения приложение создаёт два движения одной партии:

- расход с основного склада;
- приход на склад для экспериментов.

Количество в двух движениях одинаковое. Поэтому общий запас не меняется.

### Возврат на основной склад

1. Выбери `Для экспериментов`.
2. Нажми на строку партии.
3. Выбери «Вернуть на основной».
4. Укажи количество, дату, причину и комментарий.
5. Сохрани операцию.

Возврат разрешён до конца срока годности включительно. После окончания срока приложение блокирует возврат.

Срок считается так:

```text
дата партии + срок годности товара в днях
```

Если срок годности товара не задан, ограничение по возврату не применяется.

### Списание

1. Выбери `Для экспериментов`.
2. Нажми на строку партии.
3. Выбери «Списать».
4. Укажи использованное количество.
5. Выбери причину.
6. Добавь комментарий, если он нужен.
7. Проверь стоимость списания.
8. Сохрани операцию.

Списание создаёт одно расходное движение с выбранного склада.

Для сырья, использованного в опыте, выбирай причину «Эксперимент». Отдельная запись в журнале опытов не создаётся.

## Причины операций

Доступны причины: эксперимент, истёк срок, пробник, порча, возврат и прочее.

Причина хранится отдельным полем транзакции. Комментарий остаётся свободным текстом.

Примеры комментариев:

- `Пробник от нового поставщика`;
- `Использовано для проверки растворимости`;
- `Повреждена упаковка`;
- `Возвращено после проверки качества`.

## Проверка количества

Для переноса и списания количество должно:

- быть больше нуля;
- не превышать остаток партии на выбранном складе.

Можно перенести или списать часть партии. Остальная часть останется на прежнем складе.

## Период на экране склада

Склад показывает состояние на конец выбранного периода. Операции после верхней границы периода не видны.

Пример:

- конец периода на экране — `23:42`;
- перенос сохранён в `23:48:40`;
- экран показывает состояние до переноса.

Чтобы увидеть новое состояние, поставь конец периода позже времени операции и нажми «Поиск».

Это относится к обоим складам. Если перенос ещё не попал в выбранный период, партия будет видна на основном складе и не будет видна на складе для экспериментов.

## История партии

В меню партии есть действие «История партии». История показывает дату, остатки, приход, расход, склад и причину операции.

У переноса видны обе стороны: расход с одного склада и приход на другой.

## Себестоимость

При переносе себестоимость партии не меняется. Одна и та же партия сохраняет прежнюю цену за килограмм на обоих складах.

Стоимость выбранного количества считается так:

```text
стоимость = количество × себестоимость партии
```

Внутри базы количество хранится в тысячных долях единицы. Для килограммов это граммы:

```text
стоимость в копейках = количество в граммах × себестоимость в копейках за кг / 1000
```

### Если себестоимость не рассчитана

Приложение показывает предупреждение. Списание разрешается только после отдельного подтверждения.

В этом случае в прибыльность попадёт `0 ₽`, а количество со склада спишется. Такое списание нужно проверить позже, когда появится себестоимость партии.

## Влияние на прибыльность

### Перенос

Перенос не влияет на прибыльность. Материал остаётся тем же активом, меняется только место хранения.

### Списание

Списание уменьшает прибыль на себестоимость списанного материала:

```text
объём × себестоимость партии
```

В «Прибыльности» сумма:

- входит в «Общие расходы»;
- показывается как «Списания материалов»;
- один раз уменьшает общую прибыль.

Отдельной строки «Расходы на эксперименты» нет. Все причины списания объединены в «Списания материалов».

Списание учитывается по дате транзакции. Если конец периода раньше времени списания, расход не будет виден.

## Влияние на деньги

Во вкладке «Деньги» перенос и списание не показываются.

Причины:

- деньги ушли при покупке сырья;
- перенос не создаёт платёж;
- при списании деньги со счёта или из кассы повторно не уходят.

Если создать второй денежный расход при списании, одна закупка уменьшит деньги два раза.

| Операция | Остаток | Материальные запасы | Прибыль | Деньги |
|---|---:|---:|---:|---:|
| Покупка | увеличивается | увеличиваются | зависит от модели расходов | уменьшаются |
| Перенос | меняется по складам | без изменений | без изменений | без изменений |
| Списание | уменьшается | уменьшаются | уменьшается | без изменений |

Вкладка «Деньги» показывает движение денег, а не полный баланс активов предприятия.

## Пример расчёта

Себестоимость партии — `237,27 ₽/кг`.

Перенесено `20 кг`:

```text
20 × 237,27 = 4 745,40 ₽
```

Перенос не создаёт расход. На складе для экспериментов находится запас стоимостью `4 745,40 ₽`.

Списано `5 кг`:

```text
5 × 237,27 = 1 186,35 ₽
```

Результат:

- прибыль уменьшается на `1 186,35 ₽`;
- денежного движения нет;
- остаётся `15 кг`;
- стоимость остатка — `3 559,05 ₽`.

## Что использует только основной склад

Остатки `EXPERIMENTAL` не участвуют в:

- выборе сырья для ОПЗС;
- выборе партий для продажи;
- расчёте доступных партий;
- расчёте страхового запаса;
- уведомлениях о приближении срока годности.

После полного переноса партии с основного склада уведомление о её сроке исчезает. При частичном переносе оно останется, пока на основном складе есть остаток.

## Хранение в Room

Версия Room — `10`.

В `batch_movement` есть поле `storage_location` со значениями `MAIN` и `EXPERIMENTAL`. Старые движения получают `MAIN`.

В `transact` есть поле `stock_operation_reason`.

Перенос использует тип `STORAGE_TRANSFER`, списание — `WRITE_OFF`.

Перенос хранится как одна транзакция и два движения партии. Списание — как одна транзакция и одно движение.

## Синхронизация YDB

В mirror-схеме YDB есть nullable-поля:

- `batch_movement.storage_location`;
- `transact.stock_operation_reason`.

Пустое значение `storage_location` читается как `MAIN`. Это нужно для старых строк YDB.

Обновлены Room-снимки, mirror-модели, YDB-кодеки, локальное применение строк, сравнение конфликтов и восстановление пустой Room-БД.

Tombstone и порядок удаления не менялись. Склад и причина являются частью существующих строк транзакций и движений партий.

SQL миграции:

```text
database/ydb/migrate_storage_locations_v2.sql
```

### Текущее состояние общей YDB

После применения проверено:

- `batch_movement.storage_location` существует;
- `transact.stock_operation_reason` существует;
- сохранены 219 старых движений партий;
- сохранены 89 старых транзакций;
- старые значения остались пустыми и читаются новым клиентом как `MAIN`;

## Порядок выпуска

1. Добавить nullable-поля в общую YDB.
2. Проверить схему через `ydb scheme describe`.
3. Обновить все клиенты.
4. Проверить синхронизацию.
5. Только после этого создавать `STORAGE_TRANSFER`.

Старый клиент может не распознать новый тип транзакции.

## Автоматические проверки

Проверяются:

- миграция Room `9 → 10`;
- назначение старым движениям склада `MAIN`;
- частичный перенос и неизменность общего запаса;
- возврат до конца срока и запрет после него;
- списание с выбранного склада;
- отсутствие `ExpenseBD` и денежного движения;
- уменьшение прибыли на себестоимость;
- восстановление пустой Room-БД из mirror;
- конфликты синхронизации;
- формы транзакций;
- общий `smokeDesktop`.

## Частые вопросы

### Почему партия после переноса всё ещё на основном складе?

Проверь конец периода. Перенос мог быть сохранён позже верхней границы.

### Почему склад для экспериментов пустой?

Проверь выбранный склад, период, время переноса и кнопку «Поиск».

### Почему списание не видно в прибыльности?

Дата списания должна попадать в выбранный период «Прибыльности».

### Почему списания нет в деньгах?

При списании нет нового платежа. Деньги были потрачены при покупке.

### Можно ли вернуть просроченную партию?

Нет. Возврат после конца срока блокируется.

### Можно ли привязать списание к опыту?

Нет. В первой версии связи с журналом «Эксперименты» нет.

## Ограничения первой версии

- Есть только два фиксированных склада.
- Нельзя создавать дополнительные места хранения.
- Нет отчёта по расходам каждого опыта.
- Нет связи с конкретной записью эксперимента.
- Верхняя граница периода после операции не обновляется автоматически.
- Денежный отчёт не показывает стоимость материальных активов.

## Короткая памятка

```text
Перенос = два складских движения, 0 ₽ расходов, 0 ₽ денежных движений.
Списание = одно складское движение, расход по себестоимости, 0 ₽ денежных движений.
Производство, продажи, страховой запас и сроки = только MAIN.
Если операция не видна = сначала проверить период.
```
